# structured-report-md-to-html

## 中文名

结构化报告 Markdown 转 HTML

## 定位

把一份已经写好的结构化 Markdown 报告，转成一种安静、清晰、适合交接和归档的单文件 HTML 文档。

它不是“通用 Markdown 渲染器”，而是更像一种固定文档体裁：

- 左侧可折返浏览的目录
- 右侧连续阅读的正文
- 强语义的提示块、风险块、流程块、证据块
- 大量表格、命令、验证记录也能保持可读
- 适合作为报告、手册、验证记录、接手文档长期保存

## 适合

- 项目进展报告
- 技术交接文档
- 部署 / 运维操作手册
- 验证记录、测试证据、排查指南
- 一份 Markdown 已有较强层级结构，但需要更稳定、正式、可阅读的 HTML 交付

## 不适合

- 营销页、产品官网、活动页
- 幻灯片式网页 PPT
- 高视觉密度海报
- 只有零散笔记、没有清晰章节结构的 Markdown
- 期待“完全自动无判断转换”的场景

## 输出目标

输出应满足以下条件：

- 单文件 HTML，可直接本地打开
- 不依赖外部 CSS 或 JS
- 在桌面端有 sticky 目录，在移动端自动退化为单栏
- 标题、表格、代码块、提示块、FAQ 都有稳定样式
- 保持 Markdown 中的事实内容、表格数据、命令文本准确

## 推荐输入

- 原始 Markdown 文件
- 文档标题
- 文档类型
- 预期读者
- 是否保留证据、命令、日志、FAQ、附录

如果用户没有补充说明，默认把它视为“面向接手者的结构化报告”。

## 工作方式

1. 先完整阅读 Markdown，不要一上来机械渲染。
2. 判断这份文档的主轴：
   - 是进展报告
   - 是操作手册
   - 是验证记录
   - 还是三者混合
3. 抽出一级章节，作为左侧目录来源。目录通常对应 Markdown 的 `##`。
4. 用 [assets/report-template.html](/Users/qiumengbo.123/Desktop/BemoSkills/skills/writing/structured-report-md-to-html/assets/report-template.html) 作为骨架。
5. 需要决定哪些内容应从普通段落“升级”为语义块：
   - 总结类结论 → `callout`
   - 风险 / 限制 / 待确认 → `callout-warn`
   - 提示 / 说明 / 配置背景 → `callout-tip` 或 `callout-info`
   - 流程树 / 执行链路 → `flow-box`
   - FAQ 问答 → `qa`
6. 表格、命令、日志、路径、HTTP 响应等证据内容优先保真，不要为了“好看”删掉细节。
7. 最终输出成单文件 HTML，并检查移动端是否可读。

## 版式规则

- 页面宽度控制在舒适阅读范围，不做超宽大屏样式。
- 左侧目录窄、轻、稳定；右侧正文为主。
- `h2` 是章节边界，使用更强的视觉分隔线。
- `h3`、`h4` 保持说明性，不要做过重装饰。
- 表格优先简洁、信息密度高，不使用花哨色块。
- 代码块和命令输出要等宽字体、浅灰底。
- 风险信息要显著，但整体基调仍然克制。
- 小屏时隐藏侧边目录，自动退化为单栏正文。

## 内容转译原则

- 不要把 Markdown 原样套进一个渲染器就结束。需要按“报告体裁”重组。
- 第一部分如果本质上是总结结论，优先做成一个蓝色总结块，而不是普通段落。
- “待优化”“待确认”“限制”“警告”这类内容应提升为警示块。
- 命令执行流程、调用链、部署路径这类具有层级的文本，优先转成 `flow-box`。
- “Q1 / Q2 / Q3” 这种排障内容，优先转成 FAQ 块，而不是连续段落。
- 如果验证表中有“通过 / 正常 / 成功”等状态值，可以给状态单元格加成功色。
- 保持中文章节编号的语气，例如 `一、总体结论`、`二、完成时间线`。
- 目录锚点保持稳定，可按 `sec-1`、`sec-2` 递增。

更细的组件映射见 [references/component-map.md](/Users/qiumengbo.123/Desktop/BemoSkills/skills/writing/structured-report-md-to-html/references/component-map.md)。

## 禁忌

- 不要输出成博客模板感很强的文章页。
- 不要引入深色背景、强渐变、卡片瀑布流、玻璃拟态。
- 不要把所有内容都包成卡片，报告会变散。
- 不要删除原文中的表格、证据、命令，只留下摘要。
- 不要拆成多文件资源；默认应可离线打开和转发。
- 不要滥加动画。

## 交付检查

- 标题和目录是否一致
- 所有 `##` 是否都有目录项
- 表格是否完整
- 代码块是否可横向滚动
- 提示块和警示块是否用在真正需要强调的地方
- 手机宽度下是否不会挤爆
- HTML 是否是单文件

## 常用提示词
